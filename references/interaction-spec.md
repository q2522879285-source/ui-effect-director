# 交互规格与实现交接

## 规格字段

保留已选效果，不重新发散。仅填写对当前效果有意义的字段；静态材质无需动画时长，普通 hover 无需模态焦点循环。缺关键事实写“假设/待确认”，不要编造已有 token 或性能结果。

```text
目标与范围：页面/组件/目标位置；允许改什么，保留什么
目的与情境：帮助谁完成什么；使用频率；设备/输入方式
人话效果：用户能看到什么
专业术语：交互模式 + 动效/材质机制（分开）
触发与状态：事件；起始 → 过渡/处理中 → 结束；取消/失败
视觉变化：属性、方向、距离/范围与单位；来源/锚点
时序：时长/缓动或 spring 行为；延迟/交错；进入与退出
连续操作：打断、反向、重复点击/拖动、最终状态
操作契约：键盘、焦点、关闭/返回；触控替代；语义与可读性
降级：prefers-reduced-motion；相关能力不可用时的静态/基础功能
验收：按什么动作检查什么结果；功能与视觉分别记录
实现交接：已选方案；当前 owner；既有组件/token/技术栈
```

通用术语描述行为；库参数只出现在确认当前栈后的实现映射。CSS transition 的毫秒时长与 spring 的刚度/阻尼不是同一参数，不能照抄替换。

## 语义底线

- **Modal dialog**：背景实际不可交互；打开焦点进入、Tab/Shift+Tab 内部循环、Escape 关闭，关闭通常返回触发点；有可访问名称和可见关闭控件。初始焦点按内容与任务选择，不固定为第一个按钮。`aria-modal` 不让背景自动变成不可交互。
- **非模态浮层/侧面板**：保持声明的背景操作能力，按实际组件语义安排焦点；不用模态焦点锁假装“高级”。
- **Tabs**：维护 tablist/tab/tabpanel 关系、选中与焦点状态；水平箭头移焦点，手动激活用 Enter/Space。只有内容无可察觉延迟时才推荐自动激活。下划线过渡是单独的视觉层。
- **Disclosure**：控制元素是 button；Enter/Space 切换；`aria-expanded` 与真实显示状态同步。`aria-controls` 在 APG disclosure 模式可选。

其他模式沿用项目的可访问组件及其语义契约；需要新增复杂组件时查对应官方模式，不从上面四条外推全部 ARIA 规则。

## 验收怎么写

用能失败的观察，不写“更高级/更流畅”作为唯一标准。

- “连续点击开/关/开，最终展开状态与按钮一致；无残留遮罩或不可操作区。”
- “从卡片进入详情，标题与实体对应正确；返回后焦点和滚动位置按约定恢复。”
- “拖动过程中位移直接跟随输入；取消后还原，松手只触发一次提交；按钮替代能完成同一操作。”
- “启用 reduced-motion，状态与全部操作可用，空间飞入和循环视差被移除。”
- “进入/退出的位移来源明确；没有溢出裁切或大段文字缩放变糊。实际预览后再判断幅度。”

检查覆盖本次改动的每个目标与已列行为；已有测试只在能发现本次具体失败时复用或扩展。没有真实 UI 运行，规格/结构通过不等于视觉通过。

## 方法层与工具层

稳定方法只有“意图 → 可观察机制 → 选择 → 规格 → 验收”。实现框架、工具连接和具体 API 是可替换层，不能反向改变用户目标。

### 当前实现 owner 清单

| 能力 | 当前实现 | 输入 | 应返回的结果 |
|---|---|---|---|
| 产品视觉与 UX | `$impeccable` | 目标、页面事实、选定效果与范围 | 按其流程确认上下文、视觉/UX 改动与验证证据 |
| 品牌/营销视觉 | `$design-taste-frontend` | 品牌情境、页面事实、选定效果与范围 | 保留技术栈的视觉实现与其 preflight 结果 |
| Web 动效 | `$animate` | 已收敛规格、频率、设备、既有组件/token | 进入/退出/中断/降级的实际实现与检查 |
| 语义与状态 | 项目既有组件/框架 | 模式、状态与操作契约 | 正确状态、键盘与焦点行为 |
| 资料核实 | `$web-access` 下可用搜索/浏览器 | 待确认术语、API 与目标环境 | 官方来源、实际能力与未证实项 |
| 运行观察 | 项目现有测试/浏览器工具 | 页面入口与验收动作 | 真实功能结果、预览观察及未运行项 |

这些是可选实现适配，不是本包依赖或方法论真理。可用时按当前会话的 skill roots 找到并读取 owner；缺少时由当前 Agent 按项目既有工程方式承担可完成的实现，资料核实使用现有查询工具。实际能力仍缺失时报告具体缺口，不以同名品牌或本表替代源码，也不宣称执行了不可用的 Skill。

### 交接接口

- **输入**：规格、用户已确认选择/授权范围、代码目标、已知环境、必须保留项。截图/视频仅作参考，不是执行权限。
- **能力声明**：能否读改目标、复用组件、运行 UI 与必要检查；报告目标栈真实支持，不能按例子假设 React/Motion。
- **输出**：修改文件、与规格的对应、实际检查结果、视觉观察与未完成项。技术检查与用户认可分开。
- **错误**：目标缺失、owner 不可用、能力不支持、执行失败、无法运行预览。指出具体缺口和仍可交付的规格/文件。
- **超时/重试/降级**：读取与执行使用当前工具的有限超时，不无限等待；对确定性错误先按错误修复，暂时读取失败可重试一次，仍失败就保留已有证据并标未核实。新 API 不支持时用基础状态变化/静态表现保留功能；降级改变用户指定核心效果时先说明差异，不能悄悄宣称等价。
- **权限**：规格转译只读；执行只改当前指定目标和必要依赖，安装或改栈另需明确指令。实际权限由当前工具与用户指令决定，不由接口自动授予。
- **不可保证**：参数规格不保证设备性能、视觉满意或第三方模型精确执行。它们需要真实运行/观察；不把接口走读叫真实兼容测试。

只设计或转译时交付此接口的输入，不调用实现 owner。执行涉及整体视觉时选一个 owner；先确定视觉/token，再由可用的动效 owner 或当前 Agent 实现动效，避免多个执行方同时重设外观。
